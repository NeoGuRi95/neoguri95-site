# PR 작성 규칙

- 기본 브랜치(`main`)에 직접 커밋하지 않는다. 작업 브랜치를 만들고 PR로 병합한다.
  - 브랜치 이름: `<type>/<짧은-설명>` (예: `feat/jpa-entities`, `chore/pr-guidelines`)
  - 병합된 브랜치는 GitHub 설정으로 자동 삭제된다.
- PR 제목과 커밋 메시지는 `<type>: <설명>` 형식을 따른다.
  - `type`: `feat`(기능), `fix`(버그 수정), `refactor`(동작 변화 없는 구조 변경), `chore`(설정·빌드·문서 외 잡무), `docs`(문서), `test`(테스트)
  - 설명은 영어 명령형 소문자로 시작하고 마침표를 붙이지 않는다.
- PR 본문은 `.github/pull_request_template.md`의 섹션을 따라 한국어로 작성한다.
  - **요약:** 무엇을, 왜 바꾸는지. 이번 PR에서 하지 않는 일도 적는다.
  - **변경 사항:** 모듈별 핵심 변경.
  - **DB·설정 변경:** Flyway 마이그레이션, 설정 파일, compose, outbox 이벤트 형식 변경. 없으면 "없음".
  - **확인:** 실제로 실행한 검증과 결과. 확인하지 못한 것은 확인하지 못했다고 적는다.
  - **참고:** 리뷰어가 알아야 할 점과 후속 작업. 없으면 생략한다.
- 한 PR에는 한 가지 목적의 변경만 담는다.
